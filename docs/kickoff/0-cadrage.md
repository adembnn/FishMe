# 0. Cadrage — Build Challenge Apple (Unaite, MWM, Apple, Command+F)

**Brief officiel (organisateur)** : « on cherche des apps monétisées, publiées au plus tard vendredi à 15h, mises à jour après le Build Challenge, et qui durent. Pas des projets qui prennent la poussière sur GitHub ou l'App Store. » Livrable d'inscription : pitch 1 phrase, pitch 1 paragraphe, public visé, solution et différence, équipe 3-4 (nom, email, école). Technos suggérées : Apple Intelligence / Foundation Models, IA on-device, Liquid Glass, Siri / App Intents, StoreKit.

**Critères retenus (slides MWM du before hack)** :
- Produit : résoudre un problème clair ; premier moment utile très rapide ; une raison de revenir.
- Monétisation : définir la valeur payée ; aligner l'offre ; tester prix, durée, essai.
- Acquisition : savoir qui on vise ; promesse facile à comprendre ; coût d'acquisition soutenable.
- Purpose : « [quoi] pour [qui], pour [quand] ». Trouve-le, puis défends-le.
- Notes d'Adem : tendances WWDC, Apple Design Awards, Private Cloud Compute, « l'omission par design » (grug : simplicité).

**Kit MWM** : projet dans le compte App Store Connect de MWM (pas besoin de compte dev), MCP MWM, SDK Spark Flash intégré, fichier StoreKit de test, iPhone de test sur place.

**Équipe** : 3 étudiants M1 ESSEC (21-22 ans), profils business, aucun n'a shippé d'app iOS, très à l'aise pour builder avec l'IA. Pas d'expertise domaine revendiquée (pas de fintech/sécurité).

**Ambition** : c) produit réel, vendu, maintenu.

## Carte de rejet
- Pas monétisable de façon crédible (personne ne paie, ou payeur ≠ utilisateur sans canal).
- Usage ponctuel, aucune raison de revenir.
- Premier moment utile lent (onboarding lourd, données à saisir avant de voir la valeur).
- Promesse pas compréhensible en une phrase « [quoi] pour [qui], pour [quand] ».
- Déjà fait correctement par une app installée par défaut ou leader évident.
- Irréalisable en une semaine par des non-développeurs aidés par l'IA (backend lourd, matériel, données propriétaires, validation réglementaire).
- Risque de rejet App Store (santé/finance réglementées, contenu utilisateur non modéré, scraping).
- IA décorative : si on retire l'IA, ça marche encore → perdu.
- Interdits d'office : chatbot, dashboard, « plateforme qui aide X », assistant généraliste.
