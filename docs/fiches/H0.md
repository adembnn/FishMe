# H0 Atelier
Préparé par Claude avant jeudi, gardé par A · branche `lot/atelier` · étapes toutes · avant jeudi

## But
L'atelier autour des agents : il briefe chaque session Claude Code sur son lot, l'empêche d'écrire hors de son dossier, refuse « fini » tant que les tests sont rouges, relit chaque lot avant sa fusion, et laisse l'agent voir l'app dans le simulateur. Il protège aussi la personne qui travaille sans Claude : les mêmes règles tournent dans les crochets de git.

## Avant de commencer
- [ ] `docs/lots.md` à jour : chaque lot a sa branche et ses dossiers. Preuve : `python3 outils/atelier/lots.py verifier` sort 0
- [ ] Sur chaque Mac et dans le cloud : `scripts/docteur.sh` tout vert, ou chaque ligne rouge avec sa commande de réparation

## Dossiers
- Permis : `.claude/`, `.githooks/`, `.github/`, `.mcp.json`, `.gitignore`, `scripts/`, `outils/atelier/`, `fastlane/`.
- Interdit : le code de l'app (`App/`, `Packages/`, `Widget/`) et les données (`Resources/`, `outils/hubeau/`).

## Contrat
- `docs/lots.md` est la seule source : la colonne « Branche » relie une branche à un lot, la colonne « Dossier » dit où il écrit. Un lot qui possède `App/<X>/` possède aussi `AppTests/<X>/` et `AppUITests/<X>/`. `docs/`, `reports/`, `CLAUDE.md` et `README.md` sont communs.
- `scripts/lot.sh <code>` crée la copie de travail du lot (un worktree git : un second dossier du même dépôt, sur la branche du lot) et branche les crochets de git.
- Dans une session Claude Code : au démarrage, la fiche du lot est injectée ; avant chaque écriture, le chemin est contrôlé ; avant la fin d'un tour, `scripts/verif.sh --rapide` doit être vert.
- `scripts/verif.sh` : documents, tests de `Core` (Swift natif, sinon Docker `swift:6.4`), tests de l'app sur Mac. Chaque partie sautée le dit, jamais un vert silencieux.
- `scripts/fusionner.sh` : seul chemin vers `main` ; refuse un fichier hors du lot ou un test rouge.
- Relecteurs (`.claude/agents/`) : règles App Store, code iPhone, règles de pêche ; revue finale en Opus avant l'envoi à Apple.
- Commandes : `/lot`, `/fusion`, `/ecran`, `/envoi`.

## Consigne à coller dans Claude Code
```text
Lis CLAUDE.md, docs/lots.md (ligne H0) et docs/fiches/H0.md. Travaille seulement dans les dossiers de H0. Toute règle nouvelle
(un dossier, une branche, un garde-fou) se lit dans docs/lots.md, jamais en dur dans un script. Après chaque modification,
lance python3 outils/atelier/essai.py et colle sa sortie ; ne dis pas « fini » sans elle.
```

## Test « fini »
Commande : `python3 outils/atelier/essai.py`
1. Chaque erreur provoquée (écriture hors dossier, commit hors dossier, « fini » avec un test rouge, fusion d'un test rouge, lecture du `.env`) est bloquée, avec un message qui dit quoi faire.
2. Chaque cas permis passe (écriture dans son dossier, dans `docs/`, hors du dépôt).
3. `scripts/docteur.sh` sur un Mac : Xcode 27, simulateur iOS 27, XcodeBuildMCP, fastlane, crochets de git branchés.

## Pièges
- Un garde-fou trop strict bloque le travail jeudi. Parade : chaque refus nomme le lot propriétaire et la commande à lancer ; `ATELIER_LIBRE=1` lève les contrôles de Claude Code pour une urgence, et le dit à chaque écriture.
- Le contrôle de fin de tour relance les tests à chaque arrêt de l'agent. Parade : `--rapide` ne teste que le lot touché ; au bout de 3 refus, l'agent peut s'arrêter mais doit écrire que c'est rouge.
- La partie Mac (simulateur, envoi) ne se vérifie pas dans le cloud. Parade : `scripts/docteur.sh` sur chaque Mac, mercredi soir.

## Si ça coince
- Un garde-fou se trompe : corrige `docs/lots.md` (la règle), pas le script.
- Le cloud n'a pas Swift : `sudo dockerd &`, puis `docker pull swift:6.4` (vérifié le 13 oct. : Swift 6.4, Swift Testing et `swift format` tournent).
