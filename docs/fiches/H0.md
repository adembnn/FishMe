# H0 Atelier
A · branche `lot/atelier` (ta copie de travail du projet) · étapes toutes · fait le 13 oct. ; reste la reprise des agents de Titouan et du banc d'essai, 1 h (estimation de `lots.md`)

## But
L'atelier autour des agents : il briefe chaque session Claude Code sur son lot, l'empêche d'écrire hors de son dossier, refuse « fini » tant que les tests sont rouges, relit chaque lot avant sa fusion, et laisse l'agent voir l'app dans le simulateur. Il protège aussi la personne qui travaille sans Claude : les mêmes règles tournent dans les crochets de git (les contrôles que git lance seul à chaque commit).
Ce qui reste : (1) reprendre dans l'atelier les meilleurs agents de Titouan, réécrits en Sonnet ; (2) tenir le banc d'essai (`/banc`) branché, pour qu'il passe sur chaque lot qui touche `App/` ; (3) bloquer les lots de la mise à jour tant que la version soumise n'est pas partie (étiquette `v1.0-soumise`, ci-dessous).

## Contrat
- `docs/lots.md` est la seule source : la colonne « Branche » relie une branche à un lot, la colonne « Dossier » dit où il écrit. Un lot qui possède `App/<X>/` possède aussi `AppTests/<X>/` et `AppUITests/<X>/`. `docs/`, `reports/`, `CLAUDE.md` et `README.md` sont communs.
- `scripts/lot.sh <code>` crée la copie de travail du lot (un worktree git : un second dossier du même dépôt, sur la branche du lot). `scripts/verif.sh` vérifie, `scripts/fusionner.sh` est le seul chemin vers `main`. Une partie sautée est dite, jamais un vert silencieux.
- Quatre agents de Titouan repris, source `harnais-titouan/.claude/agents/` (`vision.md` §6). Chacun est réécrit pour notre plan : `model: sonnet`, lecture seule (ni Write ni Edit), 20 lignes de sortie au plus, `name` égal au nom du fichier.
  - `testeur-identification` : mesure top-3, top-1 et confusions sur le jeu de test de R1. Les seuils sont ceux de `lots.md` (bonne espèce parmi 3 dans 90 % des cas, en premier dans 70 %, seuils proposés), pas les 85 % et 60 % de Titouan.
  - `revue-ux-2taps` : compte les touchers d'un parcours en lisant le code (utile sans Mac, dans une session cloud de B). Cibles de `lots.md` : 3 touchers au plus pour « Choisir un autre spot », 2 pour un lien de Mon club. Le « capture en 2 touchers » de Titouan suppose une app qui s'ouvre sur l'appareil photo : la nôtre s'ouvre sur la carte.
  - `coupeur` : dit quoi couper quand une porte saute. Il lit « Si une porte saute » de `docs/lots.md` ; le « gel vendredi 11 h » de Titouan n'existe pas dans notre plan, on l'enlève.
  - `verificateur-wording` : relit les textes affichés contre `docs/banc/mots-interdits.md`. Chez Titouan, tout verdict est interdit ; chez nous, la liste de contrôle sourcée est permise et « tu peux la garder » reste interdit (par défaut, question 1 de `README.md`).
  - Aucun ne cite « Bredouille » (nom de son projet) : l'app s'appelle FishMe (Adem, 15 oct.).
- Les trois skills de Titouan que `vision.md` §6 reprend (`anti-sur-ingenierie`, `liquid-glass-swiftui`, `zero-friction-2-taps`) : même traitement, mais `lots.md` ne chiffre que les agents. Fais les agents d'abord.

## Test « fini »
Commandes : `python3 outils/atelier/essai.py`, `python3 outils/atelier/verifier_claude.py`, `scripts/docteur.sh`.
1. Chaque erreur provoquée (écriture hors dossier, commit hors dossier, « fini » avec un test rouge, fusion d'un test rouge, lecture du `.env`) est bloquée, avec un message qui dit quoi faire. Chaque cas permis passe.
2. `verifier_claude.py` affiche « relecteurs et commandes : N fichiers conformes » avec les 4 agents repris en plus, tous en `sonnet`.
3. `grep -rn "Bredouille" .claude/` n'affiche rien (`verifier_claude.py` refuse déjà les tirets cadratins).
4. Sur un Mac, `/banc L0` écrit un rapport dans `reports/banc/` (il joue sur l'app vivante). Sans Mac, il le dit et joue sur les captures : c'est « non vérifié » pour la partie écran.
5. `scripts/docteur.sh` sur un Mac : Xcode 27, simulateur iOS 27, XcodeBuildMCP, fastlane, crochets de git branchés.
6. Sans l'étiquette `v1.0-soumise`, `scripts/fusionner.sh lot/amis` refuse et dit pourquoi (même chose pour `lot/ou-chercher`, `lot/ecran-verrouille`, `lot/veille`, `lot/aquarium`) ; avec l'étiquette, il passe à la suite de ses contrôles.

## Pièges
- Un garde-fou trop strict bloque le travail. Parade : chaque refus nomme le lot propriétaire et la commande à lancer ; `ATELIER_LIBRE=1` lève les contrôles de Claude Code pour une urgence, et le dit à chaque écriture.
- Le contrôle de fin de tour relance les tests à chaque arrêt de l'agent. Parade : `--rapide` ne teste que le lot touché ; au bout de 3 refus, l'agent peut s'arrêter mais doit écrire que c'est rouge.
- Les agents de Titouan portent les chiffres d'un autre plan (4 onglets, 5 classes de rareté, 17 agents sur 20 en Opus). Copiés tels quels, ils contredisent `lots.md`. Parade : relis chaque seuil contre `docs/lots.md` avant de l'écrire.
- Un `/banc` complet lance plusieurs agents Sonnet (3 passages par profil, 6 simulateurs au plus). Parade : un lot ne joue que les profils de ses étapes ; l'argument `tout` seulement si Adem le demande.
- La partie Mac (simulateur, envoi) ne se vérifie pas dans le cloud. Parade : `scripts/docteur.sh` sur chaque Mac.

## Si ça coince
- Un garde-fou se trompe : corrige `docs/lots.md` (la règle), pas le script.
- Un agent repris est refusé par `verifier_claude.py` : lis son message ; c'est souvent un « : » dans une valeur d'en-tête sans guillemets. Corrige l'en-tête, pas le script.
- La branche de Titouan manque : demande-lui de la pousser ; sans elle, écris les quatre agents depuis les extraits de `vision.md` §6, plus courts.
- Le cloud n'a pas Swift : `sudo dockerd &`, puis `docker pull swift:6.4` (vérifié le 13 oct. : Swift 6.4, Swift Testing et `swift format` tournent).
