# S1 Fiche et conformité
C (sans Mac) pour l'écriture, S (Sullyvan) pour la relecture · branche `lot/store` (ta copie de travail du projet) · étapes toutes · 3 à 6 h (estimation) · dépend du nom de l'app · porte 2 (L0 + 7 h) : fiche prête ; ensuite les notes pour le relecteur

## But
Que le relecteur d'Apple (l'employé qui teste l'app avant sa publication) n'ait aucun motif de refus : une fiche qui promet ce que le build fait, des pages web, des notes en anglais, des captures prises sur le build. Un refus coûte une file d'attente entière (au moins 24 h) : on vise un seul tour. Le serveur MCP de MWM (le branchement de Claude Code à l'outil de publication de MWM) publie les pages et envoie les textes ; la soumission à Apple reste un clic humain.

## Avant de commencer
- [ ] Nom de l'app choisi par Adem (30 caractères au plus ; ni « Pescedex », qui est la collection, ni « Frétille » ni « Bredouille »). Preuve : écrit dans `CLAUDE.md`. Sans lui, écris avec `[NOM]` et ne publie rien
- [ ] Serveur MCP de MWM déclaré dans `.mcp.json` (`console-mwm-ai`, `https://mcp.mwm.ai/mcp`), connexion OAuth avec le compte de l'équipe. Injoignable depuis le cloud : tu écris les textes ici, la publication se fait dans une session sur un Mac (A ou B) ou chez Adem. Preuve : `/mcp` y montre `console-mwm-ai` connecté
- [ ] Le README du kit MWM contient le mot de passe du compte : jamais dans git, jamais recopié dans un texte. Preuve : `grep -rni "mot de passe\|password" store/` n'affiche rien
- [ ] Rôle App Manager dans App Store Connect (le site d'Apple où le compte MWM gère l'app) pour le questionnaire d'âge et les étiquettes (lignes 5 et 6 de `app-store.md`). Preuve : tu vois la fiche de l'app
- [ ] Étapes réellement dans le build : par défaut les 9 (E1 à E9) dans leur forme minimale, sans écran verrouillé, coins publics ni amis (`parcours-demo.md`). Preuve : liste écrite dans `store/` et validée par Adem
- [ ] Vendeur légal, contact joignable, prix en euros (colonne France). Preuve : réponse de MWM au point 4 de `message-mwm.md`
- [ ] Bouton « essayer avec une photo d'exemple » dans le build TestFlight. Preuve : B le confirme à l'écran
- [ ] Liste écrite de MWM de ce que collecte Spark Flash (le manifeste du SDK donne 7 types ; ses conditions ajoutent une localisation approximative tirée de l'adresse IP, `reports/app-store.md`). Preuve : le message de MWM, rangé dans `store/` ; si le SDK tire cette localisation, « localisation approximative » est déclarée (ligne 6 de `app-store.md`)

## Dossiers
- Permis : `store/` seulement (textes de fiche, notes pour le relecteur, pages web).
- Interdit : tout `*.xcodeproj`, `App/`, `Packages/Core`, les dossiers des autres lots.

## Contrat
Ce que S1 livre (en français, sauf les notes) :
- Fiche : nom (30 caractères), sous-titre (30), catégorie principale (« Sports » par défaut, à confirmer par Adem), mots-clés (100 octets, sans nom d'app ni marque), description (4000), texte promo (170), nouveautés, copyright. La description dit la couverture réelle lue dans `regles.json` (socle national partout, règles locales pour tels départements) : elle ne dit « toute la France » que si le build la couvre. Elle dit que l'information est indicative et que l'arrêté fait foi. Jamais « tu peux la garder ».
- Tarif : le tarif fondateur (34,99 jusqu'au 31 décembre 2026, puis 49,99) n'est écrit que s'il est identique au paywall de L6 ; mensuel avec 1 semaine d'essai, annuels sans ; aucun « essai 1 mois ».
- Trois pages web : confidentialité (MWM nommé pour le SDK Spark Flash : le manifeste du kit liste 7 types de données non liés à l'identité et dit `NSPrivacyTracking` faux), conditions, assistance avec un vrai contact. Validées par MWM.
- Notes pour le relecteur, en anglais, 4000 octets au plus : couverture, coordonnées d'un quai (Charenton), chemin vers la photo d'exemple, démarrage d'une session (la 1re est toujours permise et son lieu devient le spot gratuit ; hors de France, elle marche avec « hors de France : aucune règle française » jusqu'à la fin de session et au paywall), chemin d'achat, vidéo de 60 s (B), avertissement légal, services externes (OFB, OpenStreetMap, Spark Flash, IA d'Apple sur l'appareil), « l'IA propose, l'humain confirme, la table décide ». Pas de compte à l'ouverture, donc pas de compte démo.
- Captures prises sur le build TestFlight par B (ligne 4 de `app-store.md`) ; si le MCP les met en forme, il part de vraies captures.
- Une ligne de fiche = une étape livrée. Aucune marque de Nintendo, rien qui vise les enfants, ni cadre jaune ni effet holographique. « Pescedex » seulement comme nom de la collection.
- Chaque envoi par le MCP (`publish_legal_document`, `send_store_listing`, `update_app_store_screenshots`, `update_app_store_header`, `create_store_version`, `publish_landing_page`) demande la confirmation d'Adem (réglage `ask` de `.claude/settings.json`). `submit_store_version_for_review` reste un clic humain.

## Test « fini »
Commande : `scripts/fusionner.sh lot/store`. Puis :
1. Check-list de `app-store.md` : lignes 2, 3, 5, 6 et 11 par toi (5 et 6 sur le web ; les étiquettes avec MWM), ligne 4 par B.
2. Fiche écrite depuis le build TestFlight : chaque ligne correspond à un écran que A ou B a vu sur l'iPhone.
3. Les pages sont publiées par le MCP après la confirmation d'Adem, leurs liens s'ouvrent, MWM les a validées.
4. `wc -c` sur le fichier des notes donne 4000 ou moins.
5. `grep -rniE "pok[eé]" store/` n'affiche rien ; `grep -rniE "lorem|TODO|fake|mock|example\.com|nomprovisoire|à compléter" store/` n'affiche rien avant l'envoi ; `grep -rniE "viendra|bientôt|prochainement" App/` n'affiche rien avant l'archive (aucun onglet vide ne part chez Apple).
6. Relu par S : chaque phrase de la fiche comparée aux captures ; son nom est dans le message du commit.
7. « Première minute » sur TestFlight (S) : position refusée, mode avion, hors Île-de-France, sans plantage ; position à Cupertino, la 1re session va jusqu'au paywall, comme le disent les notes. `git diff --name-only main` ne montre que `store/`.

## Pièges
- La fiche promet plus que le build (refus R7 de `app-store.md`). Adem vise toute la France : la fiche suit le build, pas l'ambition. Parade : écrire depuis la liste des étapes livrées et la comparer aux captures.
- Le relecteur n'a pas de poisson (refus R1). Parade : les notes donnent la photo d'exemple, les coordonnées d'un quai et le chemin vers l'achat test ; B filme le parcours en 60 s.
- Textes provisoires (règle 2.1). Parade : les `grep` du test 5.
- Un onglet dont le lot n'est pas fusionné part chez Apple avec son vide « ce qui viendra » (règles 2.1 et 2.3.1). Parade : avant l'archive, A le retire ou le réduit à un écran qui marche ; le dernier `grep` du test 5 le vérifie.
- Les prix du kit sont en dollars : lis les euros dans App Store Connect (colonne France) et suis `CLAUDE.md`.
- Le serveur MCP de MWM est injoignable depuis le cloud : passe la main à un Mac.
