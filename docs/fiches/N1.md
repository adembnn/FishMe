## But
Habiller l'aquarium sans toucher à rien d'autre : un menu « Décors » dans l'aquarium propose des habillages (fond, éclairage, petits objets), certains de saison. Le pêcheur ouvre un aperçu, puis « Appliquer » : le skin s'applique à l'aquarium de l'app et au widget « Mon aquarium ». Les décors gagnés en pêchant (L14) restent gagnés en pêchant ; les thèmes de saison sont inclus dans le Pro ; ils reviennent chaque année aux mêmes dates. Purement cosmétique : aucun effet sur la rareté, la taille ni le Pescedex, aucun tirage au hasard payant, pas de compte à rebours.

## Contrat
### Interface publique de `Core` (pure, testable sous Linux, `Packages/Core/Sources/Core/Skins/`)
- `public struct IdentifiantSkin: Hashable, Codable, Sendable` : chaîne stable (`riviere`, `etang`, `grotte`, `halloween`, `noel`, `ouverture-truite`, `ete`) ; `static let parDefaut` (`riviere`, le décor de départ, toujours disponible).
- `public enum ThemeSaison: String, Codable, Sendable, CaseIterable` : `halloween`, `noel`, `ouvertureTruite`, `ete` (on ajoute `automne` plus tard sans casser les fichiers lus).
- `public struct FenetreAnnuelle: Sendable, Equatable` : `moisDebut`, `jourDebut`, `moisFin`, `jourFin` ; sait **traverser le 31 décembre** (Noël) ; `func contient(_ date: Date, calendrier: Calendar) -> Bool` ; `func prochaineOuverture(apres date: Date, calendrier: Calendar) -> Date` (la saison est comptée jour entier, jamais à l'heure). Aucun compte à rebours n'en est tiré : l'écran écrit « Revient en octobre », jamais « plus que 3 jours ».
- `public enum OrigineSkin: Sendable, Equatable` : `.gagne(CritereDecor)` ; `.pro` (inclus dans le Pro, toute l'année) ; `.saison(ThemeSaison, FenetreAnnuelle)` (Pro, appliquable pendant sa fenêtre) ; `.offertParDefi` (gratuit quand un défi le débloque, voir `ContexteSkin.defisTermines`).
- `public enum CritereDecor: Sendable, Equatable` : `.especesDifferentes(Int)`, `.sessions(Int)`, `.unLegendaire`.
- `public struct ProgressionPecheur: Sendable, Equatable` : `especesDifferentes`, `sessions`, `legendairesPris` (trois entiers, rien d'autre : ni lieu, ni date de prise, ni photo) ; `func satisfait(_ c: CritereDecor) -> Bool`.
- `public struct Skin: Sendable, Equatable, Identifiable` : `id`, `nom`, `origine`, `ordre`, `poidsApproxOctets` (pour le budget, voir Critères).
- `public enum CatalogueSkins` : `static let tous: [Skin]` (7 au départ, ids uniques, `parDefaut` présent et `.gagne`), `static func skin(_ id: IdentifiantSkin) -> Skin?`.
- `public struct ContexteSkin: Sendable` : `date`, `calendrier` (injecté, `Europe/Paris` en production, **jamais `Date.now` dans la règle**), `abonne: Bool`, `progression: ProgressionPecheur`, `defisTermines: Set<IdentifiantSkin>`.
- `public enum StatutSkin: Sendable, Equatable` : `.disponible` · `.apercuSeulement(raison: RaisonVerrou)` · `.horsSaison(revientLe: Date)` · `.aGagner(CritereDecor)`. `RaisonVerrou` : `.proRequis`.
- `public func statut(_ skin: Skin, dans contexte: ContexteSkin) -> StatutSkin` : **la règle « quel skin est disponible, à quelle date, pour qui »** :
  - `.gagne(c)` : `.disponible` si `contexte.progression.satisfait(c)`, sinon `.aGagner(c)` ; **jamais** verrouillé par le Pro, jamais retiré une fois gagné ;
  - `.pro` : `.disponible` si `abonne`, sinon `.apercuSeulement(.proRequis)` ;
  - `.saison(_, f)` : `.horsSaison(revientLe:)` si la date n'est pas dans `f` ; sinon `.disponible` si `abonne`, sinon `.apercuSeulement(.proRequis)` ;
  - `.offertParDefi` : `.disponible` si l'id est dans `defisTermines`, sinon comme `.pro`.
  - Un skin qui a un défi terminé est `.disponible` même sans Pro et même hors saison (la récompense est à vie).
- `public func appliquable(_ id: IdentifiantSkin, choisiActuel: IdentifiantSkin?, dans: ContexteSkin) -> IdentifiantSkin` : l'id à afficher réellement. Règles : un id inconnu → `parDefaut` ; un skin Pro appliqué dont l'abonnement a pris fin → **le dernier décor gagné** (jamais un écran vide) ; un skin de saison appliqué dont la fenêtre est close **reste affiché** (décision 4 d'Adem, à confirmer) tant que le pêcheur n'en choisit pas un autre.
- Aucune dépendance à `Rarete`, `Prise`, `Pescedex`, `Lieu` : tests grep et `import` dans le test de frontière.

### App (`App/Aquarium/Skins/`, SwiftUI, tout iPhone en portrait)
- `SkinsGalerieView` : ouverte par un menu « Décors » dans l'aquarium (le bouton est posé par L14 / A, voir « Demandes à L25 ») ; trois rangées, **Mes décors** (gagnés en pêchant), **En ce moment** (saison ouverte, Pro), **Reviennent chaque année** (saisons closes, avec « Revient en novembre », sans date de fin affichée en compte à rebours) ; une vignette par skin ; image, pas de liste de noms ; aucune barre de défilement visible (`.scrollIndicators(.hidden)`).

- `ChoixSkin` : `@AppStorage("aquarium.skin")` (valeur = `IdentifiantSkin`), lu et corrigé par `appliquable(...)` au rendu ; pas de réseau, pas de compte.

- Le skin décide de **trois choses seulement** : l'image de fond (grand, moyen, petit), une teinte d'éclairage, de 0 à 3 petits objets posés (citrouille, guirlande, nénuphar…) ; il ne touche ni au moteur de nage (`MoteurNage.swift`), ni aux poissons, ni à leur taille, ni aux rations, ni aux effets d'eau.

## Risques
- **Poids des images.** Sept fonds en plusieurs tailles gonflent l'app et surtout l'extension du widget, qui a une mémoire bornée ⚠ (limite exacte non vérifiée). Parade : le widget n'a que `petit` et `moyen` allégés, pas de petits objets animés ; budgets du critère 11 ; format HEIC ou PNG indexé à décider avec D1 ; vérifier l'archive avant la fusion.
- **Widget désynchronisé.** Le widget affiche un skin que l'app a retiré (Pro perdu, saison close). Parade : l'app donne l'id déjà corrigé ; le widget ne compare jamais de date ; repli sur `fond-<format>`.
- **Conflit de fichiers avec L14 et L15.** `AquariumView.swift` est à L14, le widget à L15. Parade : N1 ne démarre qu'après leur fusion, ne touche que trois lignes de `AquariumView.swift`, et écrit le reste en « Demandes à L25 ».
- **App Review.** Option (1) : le contenu d'un abonnement qui s'enrichit est admis (⚠ non revérifié dans le texte actuel des règles). Option (2) : 3.1.1, toute vente de contenu numérique passe par l'achat intégré d'Apple ; pas de lien ni de bouton vers un paiement extérieur ; les thèmes ne se « débloquent » ni par code ni par avis. Un tirage au hasard payant serait de plus soumis à l'affichage des probabilités : écarté (Q24b).
- **FOMO.** Les saisons limitées dans le temps poussent à acheter dans la précipitation. Parades : les thèmes reviennent chaque année aux mêmes dates ; le skin appliqué reste ; aucun compte à rebours, aucune notification de rappel ; on montre « Revient en octobre », pas « plus que 3 jours » ; aucun prix qui change avec la date.
- **Dates fausses ou mal reçues.** Une « Ouverture de la truite » le 1er mars n'est pas celle du département du pêcheur. Parade : nom neutre (« Ouverture ») et fenêtre large ; ⚠ je n'ai pas vérifié les dates d'ouverture ; aucune date n'est affichée comme date légale.
