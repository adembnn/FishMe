## Décisions pour Adem (à trancher avant de coder ; la valeur par défaut est celle que la fiche suppose)
1. **Où vit la liste.** Défaut : une ligne « Mes envies · N » sous l'en-tête du Pescedex (comme « Voir mon aquarium »), qui ouvre la liste en page. Écartées : un 3e volet du sélecteur (L18 retire « Amis » ; il resterait un sélecteur à un choix), un 4e onglet.
2. **Espèces protégées ou à relâcher** (`StatutEspece.protegee`, `.toujoursRelachee`, `.stadeADemander`). Défaut : pas de bouton « Je veux la pêcher » sur elles. Inciter à viser une espèce protégée serait une promesse que l'app ne veut pas tenir.
3. **Une carte « déclarée »** (déjà pêchée, sans photo) fait sortir l'espèce de la liste, comme une vraie prise. Défaut : oui.
4. **Sauvegarde iCloud.** Défaut : la liste suit le pêcheur d'un iPhone à l'autre (profil de la sauvegarde existante, rien de nouveau côté CloudKit). Repli : local seulement.
5. **Rappel à l'ouverture** (« la truite ouvre samedi ») par notification locale : hors de ce lot, au backlog (permission, texte légal à relire).
6. **Date et lieu de l'ouverture.** Défaut : le spot du pêcheur (celui de `ContexteConseils.lieu`) et la date du jour. Sans spot : « Choisis un spot pour voir l'ouverture ». Pas la zone du Pescedex : un département ne donne pas la catégorie piscicole, donc presque tout y serait « vérifie l'arrêté ».
7. **Visibilité.** Défaut : privée, jamais montrée aux amis ni au fil social (décision 1 du 19 oct. : le fil existe, la liste d'envies n'y est pas).

## But
Un pêcheur Fishbrain demande de « marquer les espèces qu'on veut pêcher » (`concurrence/06-avis-utilisateurs.md`, 4e enseignement : demandée chez Fishbrain, absente de FishMe, candidate). Dans le Pescedex et sur la fiche d'une espèce, un toucher marque « Je veux la pêcher ». « Mes envies » rassemble ces espèces, triables, et montre pour chacune ce qui est utile sans rien promettre : si la pêche est ouverte aujourd'hui d'après les règles sourcées, la règle de taille, un conseil du mois. Quand une carte de l'espèce entre au Pescedex, l'envie sort de la liste. Tout est gratuit et reste sur l'iPhone (et dans la sauvegarde iCloud privée existante).
Jamais « bon spot », jamais « chances », jamais de classement par probabilité de capture, jamais « tu peux la garder » ni « autorisé » : la ligne d'ouverture est une porte vers la source, pas un verdict. Jamais « Pokémon » ni « Pokédex ».

## Interface publique

### Core (`Packages/Core/Sources/Core/Envies/`)
```swift
public struct Envie: Sendable, Equatable, Hashable, Codable {
    public var espece: String          // Espece.id
    public var ajoutee: Date
    public var retiree: Date?          // nil : active ; sinon date de sortie (pierre tombale pour la fusion)
    public var motif: MotifRetrait?    // .pecheeLaCarteEstAuPescedex | .retireeParLePecheur
    public var modifie: Date { retiree ?? ajoutee }
}

public struct ListeEnvies: Sendable, Equatable, Codable {
    public private(set) var envies: [Envie]            // actives et pierres tombales, une par espèce
    public var actives: [Envie] { get }
    public func contient(_ espece: Espece) -> Bool     // active seulement
    public mutating func ajouter(_ espece: Espece, le date: Date)    // idempotent ; réactive une pierre tombale
    public mutating func retirer(_ espece: Espece, le date: Date)    // motif .retireeParLePecheur
    /// Les espèces dont une carte est au Pescedex sortent. Ignore les cartes d'exemple.
    public mutating func retirerLesExaucees(cartes: [Prise], le date: Date)
    /// Peut-on proposer le bouton ? Faux si protégée / toujours relâchée / stade à demander, ou déjà au Pescedex.
    public static func peutEtreMarquee(_ e: EspecePechable, cartes: [Prise]) -> Bool
    public static func fusionner(_ a: ListeEnvies, _ b: ListeEnvies) -> ListeEnvies  // par espèce, la modification la plus récente gagne
}

public enum OrdreEnvies: String, CaseIterable, Sendable { case ouvertesDAbord, recentes, alphabetique }
// Jamais d'ordre « chances », « probabilité » ou « rareté croissante » (voir les interdits).

public enum StatutOuverture: Sendable, Equatable {
    case ouverte(SourceRegle?)               // ligne .periode respectee
    case fermee(reouverture: Date?, SourceRegle?)   // ligne .periode nonRespectee
    case aVerifier                           // ligne .periode aVerifierSurPlace, ou aucune ligne .periode
    case sansSpot                            // aucun Lieu fourni
}

public struct ResumeEnvie: Sendable, Equatable {
    public var espece: EspecePechable
    public var ouverture: StatutOuverture
    public var taille: String?               // `LigneControle.phrase` de la ligne .taille, telle quelle (jamais recomposée)
    public var sourceTaille: SourceRegle?
    public var conseil: Conseil?             // le « moment » ou l'« appât » du mois, déjà filtré par l'abonnement
    public static func construire(espece: EspecePechable, controle: ResultatControle?, conseil: Conseil?) -> ResumeEnvie
    public static func trier(_ resumes: [ResumeEnvie], ordre: OrdreEnvies, liste: ListeEnvies) -> [ResumeEnvie]
}

public protocol StockageEnvies: Sendable {
    func lire() -> ListeEnvies
    func ecrire(_ liste: ListeEnvies)
}
public struct StockageEnviesFichier: StockageEnvies { public init(url: URL) }  // JSON atomique ; fichier absent ou corrompu : liste vide, jamais de plantage
```

## Contrat
- **Marquer.** Sur `FicheEspeceView` d'une espèce pas encore trouvée, un bouton `BoutonEnvieView` sous la tuile de l'espèce (1 toucher). Sur un emplacement vide du classeur, un menu contextuel (appui long) « Je veux la pêcher ». Pas de bouton sur une espèce déjà au Pescedex, ni sur une espèce protégée (décision 2).
- **Liste.** La ligne « Mes envies · N » apparaît dans le Pescedex seulement si N ≥ 1 (sinon rien, le Pescedex vide reste comme L18 l'a laissé). Elle ouvre `MesEnviesView` en page avec retour « Pescedex ».
- **Lignes.** Pour chaque espèce :
  - Ouverture à la date du jour, d'après `ResultatControle` du spot : « Ouverte aujourd'hui · arrêté » (source à un toucher), « Fermée jusqu'au 25/04 » (réutiliser le format `ExtensionsConseils.texteFermeture` : `dd/MM`, locale `fr_FR`), « Vérifie l'arrêté » avec pastille orange (`Palette.alerte`) si la ligne est à vérifier ou absente, « Choisis un spot pour voir l'ouverture » sans spot (bouton si `choisirSpot` est branché).
  - Taille : la `phrase` de la ligne `.taille` telle que `Core` la rend (ex. « Taille minimale 60 cm »), sa source à un toucher ; absente : la ligne n'existe pas, rien n'est inventé. Deux textes qui se contredisent : `Core` donne déjà la plus stricte avec les deux sources (CLAUDE.md), on l'affiche telle quelle.
  - Conseil du mois : un seul (`moment` d'abord, sinon `appat`), « Conseil du mois » ; hors saison le conseil du mois le plus proche (comportement de `ContexteConseils.affiches`) avec le mois écrit ; sans conseil la ligne disparaît.
  - Rien d'autre : ni « chances », ni « bon spot », ni indice, ni couleur de probabilité.
- **Tri.** « Ouvertes d'abord » (défaut ; à égalité, la plus récemment ajoutée, puis l'ordre alphabétique), « Récentes », « A à Z ». Le choix est gardé en `@AppStorage("envies.ordre")`.
- **Sortie.** À chaque chargement du Pescedex et avant d'afficher la liste, `retirerLesExaucees` : une espèce qui a une carte (vraie prise, gardée ou relâchée, ou déclarée ; jamais la carte d'exemple, jamais une « sortie sans prise ») est retirée avec le motif `pecheeLaCarteEstAuPescedex`. Aucune récompense ni bandeau « félicitations » ; si la carte vient d'entrer, la révélation (L18) suffit.
- **Stockage.** `StockageEnviesFichier` dans `Application Support` (URL donnée par l'app), jamais dans le dépôt, aucune coordonnée. Sauvegarde : `ProfilSauvegarde.envies` ; la fusion se fait espèce par espèce, la date de modification la plus récente gagne, une pierre tombale n'est jamais purgée (au plus 101 entrées).
- **Gratuit.** Aucun appel à `peutUtiliser(...)` pour la liste elle-même ni pour son tri ; le conseil affiché suit l'abonnement comme partout (un conseil gratuit par espèce, `ConseilsAffiches`), sans ligne « Pro » dans « Mes envies ».
- **Mots.** Interdits dans `App/Envies/` et `Core/Envies/` : « chance », « bon spot », « meilleur spot », « garanti », « à coup sûr », « tu peux la garder », « autorisé », « Pokémon », « Pokédex », « Poké ». Lire aussi `docs/banc/mots-interdits.md`.
- Peu de texte, images, aucune barre de défilement visible, tout lisible à la plus grande taille de texte (AX5), `accessibilityLabel` sur chaque bouton. `/banc N2` passe avant la fusion.

## Pièges
- **Promesse implicite.** Mettre les espèces « ouvertes » en tête peut se lire comme « elles mordent ». Parade : l'ouverture est une règle de pêche, jamais une probabilité ; texte « Ouverte aujourd'hui · arrêté » avec la source, jamais d'icône de réussite ; aucun tri par rareté ou relevés OFB.
- **Verdict légal inventé.** `Consigne.aucuneRegleSaisieNeLInterdit` n'est pas « ouvert ». Parade : « Ouverte » seulement si une ligne `.periode` est `respectee` ; sinon « Vérifie l'arrêté ».
- **Fusion qui ressuscite une envie** (« rien ne s'efface jamais par une synchro », commentaire de `FusionSauvegarde`). Parade : pierres tombales datées, la plus récente gagne, tests 7 et 16.
- **Profil ancien non décodable** : `ProfilSauvegarde` est `Codable` synthétisé ; ajouter un champ sans `decodeIfPresent` casse la lecture du profil déjà dans iCloud et efface la restauration. Parade : décodeur écrit à la main, test 7.
- **Conflit de fichiers avec L18** (même `PescedexView.swift`). Parade : N2 démarre après la fusion de L18 ; les ajouts sont des paramètres optionnels et deux endroits courts.
- **Même champ que L21/L22 dans `ProfilSauvegarde`.** Parade : ajout additif seulement ; si une autre branche a touché le fichier, rebaser avant, ne jamais résoudre un conflit en supprimant une ligne de l'autre lot.
- **Dossier qui importe un autre dossier de l'app** (ouverture, conseils). Parade : closures `EnviesExternes`, comme les autres éléments du Pescedex.
- **Code SwiftUI jamais compilé** (B n'a pas de Mac). Parade : patron des vues existantes, skill `ecrire-swift-sans-compiler`, Sullyvan compile ; aucun logique dans les vues, tout est dans `Core` et testé.
- **Espèce renommée ou retirée de `especes.json`** : une envie pointe vers un identifiant inconnu. Parade : `MesEnviesView` ignore (sans effacer) une envie dont l'espèce n'existe plus.
