# D2 Données Hub'Eau
C (sans Mac) · branche `lot/hubeau` (ta copie de travail du projet) · étapes E1 E2 E3 E6 · 2 à 4 h (estimation) · ne dépend de rien · L1 et L2 attendent ses deux fichiers (porte 1, L0 + 4 h)

## But
Fabriquer pour toute la France les deux fichiers que l'app lit : `stations-especes.json` et `rarete-departements.json`. Source : les pêches électriques de l'OFB (Office français de la biodiversité) par Hub'Eau, le guichet web gratuit des données sur l'eau. Départ : le script de Titouan du 13 oct. (cinq départements lancés, le 29 en échec), à adapter. Les fichiers partent en pièce jointe d'une release privée et ne sont jamais commités.

## Avant de commencer
- [ ] Script de Titouan copié fichier par fichier, sans fusionner sa branche : `git fetch origin titouan/harnais-bredouille`, puis `git show origin/titouan/harnais-bredouille:harnais-titouan/Tools/data-pipeline/<fichier> > outils/hubeau/<fichier>` pour `hubeau_client.py`, `fetch_hubeau.py`, `build_departments.py`, `rarity.py`, `config.json`, `tests/test_rarity.py`. Preuve : `ls outils/hubeau/`
- [ ] `departements.geojson` posé par D1. Preuve : `ls Packages/Core/Sources/Core/Resources/` le liste
- [ ] Où tourne le script : le proxy du cloud bloque Hub'Eau. Preuve : `curl -sS -o /dev/null -w "%{http_code}\n" "https://hubeau.eaufrance.fr/api/v1/etat_piscicole/stations?size=1"` ; si le code n'est pas 200, il tourne sur un Mac (A ou B) ou dans GitHub Actions
- [ ] Python 3 et `gh` connecté. Preuve : `python3 --version` et `gh auth status`

## Dossiers

- Interdit : tout `*.xcodeproj`, `App/`, `Packages/Core` (même `Resources/` : les 2 fichiers y arrivent par `scripts/donnees.sh`, de A), `.github/` (à H0 : livre le workflow en exemple dans `outils/hubeau/hubeau.yml.exemple`, A le copie).

## Contrat
- Entrée : l'API `etat_piscicole` (stations, opérations = une pêche à une date et un lieu, observations) et les 14 espèces par code Sandre : brochet 2151, sandre 2195, perche 2193, black-bass 2053, silure 2238, truite fario 2221, arc-en-ciel 2216, carpe 2110 et ses variétés (codes à relever dans Hub'Eau), gardon 2133, brème 2086, chevesne 31041, tanche 2137, barbeau 2096, ombre 2247. Joindre par `code_taxon`, pas par nom latin (Hub'Eau garde l'ancien nom du chevesne). Ne demander que ces espèces (200 codes au plus par appel).
- Ce qui change chez Titouan : toute la France au lieu de 11 pilotes ; chaque station rangée dans un seul département d'après ses coordonnées et `departements.geojson`, jamais d'après le champ de l'API ; des comptes seulement. Retire ses 5 classes (seuils 30, 12, 4, 1 %), son plafond et sa fiabilité : les 4 niveaux et leurs seuils sont dans `Core` (L1). Fenêtre : du 1er janvier de l'année en cours moins 10 (2016 pour 2026) à ce jour, plus tout l'historique.
- Sortie 1, `stations-especes.json` : par station, identifiant, position, département, nombre de pêches, année de la dernière, et pour chaque espèce le nombre de pêches où elle est vue.
- Sortie 2, `rarete-departements.json` : par département et par espèce, les pêches avec l'espèce, les pêches du département (au moins un poisson), l'année du dernier relevé, sur 10 ans et sur tout l'historique, plus la région du département et ses mêmes comptes (table INSEE à citer). Forme exacte dans `donnees.md`, figée avec L1 avant sa première lecture. En tête : source (OFB et Hub'Eau), Licence Ouverte 2.0, date de mise à jour.
- Échecs : station sans coordonnées écartée et listée dans le rapport ; espèce jamais vue dans le département absente du fichier (L1 en fait « 0 pêche sur N », légendaire) ; département sans aucune pêche : comptes régionaux, jamais une estimation.
- Publication : `gh release upload donnees stations-especes.json rarete-departements.json --clobber` (crée la release privée `donnees` si elle manque). Les fichiers déjà commités chez Titouan (`PecheCore/.../Data/departments/`, `species.json`, `Tools/data-pipeline/reports/`) sortent de git : ne les reprends pas, et dis à la personne qui fusionne son atelier de les exclure.

## Test « fini »
Commande : `python3 outils/hubeau/<script> --departement 94` (nom et options fixés dans ce lot), puis la même sans option de département pour la France.
1. Sur le 94 depuis le 1er janvier 2016 : 3 stations pêchées, 29 pêches ; gardon dans 27 (93 %), perche dans 18 (62 %) (chiffres lus le 12 oct. par un outil web : à recouper) ; un test applique les seuils de `donnees.md` aux comptes et retrouve la liste « Attendu dans le 94 ».
2. Une station n'appartient qu'à un département : le point 03082000 (la Seine à Suresnes) apparaît une seule fois.
3. `git ls-files | grep -E "stations-especes|rarete-departements"` n'affiche rien.
4. `gh release view donnees` liste les 2 fichiers, et `scripts/donnees.sh` les télécharge.
5. Le rapport liste les départements sans pêche et les stations écartées.
6. `git diff --name-only main` ne montre que `outils/hubeau/`.

## Pièges
- Réponses coupées en route : chez Titouan, le 29 a échoué (`IncompleteRead` de 2,9 Mo sur une année à 20 000 lignes, plus des erreurs 503). Parade : ne demander que les 14 espèces, `fields` réduit, `size` plus petit, suivre `next` (code 206), reprise par le cache. Son plafond de 400 requêtes par lancement est trop bas pour la France : lance par groupes de départements.
- Le champ `code_departement` de l'API range le point 03082000 tantôt dans le 93, tantôt dans le 92 : deux raretés fausses. Parade : le point dans un polygone, avec un test.
- `code_operation` est un entier côté opérations et un texte côté observations (note de Titouan) : compare-les en texte.
- Peu de pêches : le 94 en a 29 depuis 2016, Paris 36 de 1989 à 2011. Parade : garde N et l'année dans le fichier, sinon l'écran ne peut pas les afficher.
- Le plafond réel de `size` n'a pas été constaté : mesure-le, ne le suppose pas.
