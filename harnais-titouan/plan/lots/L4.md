## Objectif
Ne pas dupliquer les seuils en Swift : décoder les fichiers de département (format du pipeline, clés courtes) vers `DepartmentProfile`/`RarityInfo`, appliquer les règles que le pipeline ne connaît pas (exotique, protégée, signalement inattendu), et afficher le libellé exact. La seule source de vérité des seuils est `Tools/data-pipeline/config.json`.

## Déjà dans le dépôt le 13 octobre (constaté)
Le calcul des classes est fait par le **pipeline Python** (`rarity.py`, `config.json` : profil B 30/12/4/1 sur la fréquence en opérations, plafond 2 pour les espèces de plan d'eau, fusion de codes carpe, `fiab` si < 10 stations ou < 20 opérations) et écrit dans chaque `departments/<code>.json` (champ `k` = classe 1 à 5, `seuils` recopiés). Contrat : `RarityProvider`, `RarityInfo`.

## Interface publique à respecter
- `PipelineRarityProvider: RarityProvider` : `rarity(of:in:) -> RarityInfo?` à partir du champ `k` ; si `k` absent, recalcule depuis `p` et `seuils` du fichier.
- Règles : menacée +1 classe (plafond Remarquable) ; `.envahissante` et `.exotique` : pas de classe (L37) ; `.protege` : pas de classe à chasser ; `fiab == faible` : avertissement visible ; espèce hors relevés confirmée par l'utilisateur : « signalement inattendu » avec avertissement.
- Libellé : voir L1 (relevés de pêche scientifiques, jamais « probabilité de capture »).
